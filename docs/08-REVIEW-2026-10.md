## 2. Speed upgrades (20)

Standing: database 20 MB of 500 MB; file storage 0.4 MB of 1 GB; biggest table engine_maps, 1.5 MB in 11 rows; 19 scheduled jobs.

### 2.1 Clean out old app files on phones
The app's offline helper saves the code for every version we ship and never deletes the old copies, so the app slowly takes more space on each phone. It would keep only the current version.

- Pros: Phones stop filling up with old copies; The offline helper looks things up faster
- Cons: The first open after an update downloads the new files once, which already happens today
- Storage: No Supabase effect; frees space on members' phones · Effort: Small · Gain: 3/5

### 2.2 Instant reopen with the last data you saw
When you reopen a page, it shows the data from your last visit right away, stamped with its age, while the fresh data loads behind it. Warnings and alerts always load fresh.

- Pros: Pages appear instantly, even on one bar of signal; Pages you visited still show something offline
- Cons: For a second or two you may see data a few minutes old (always labeled); Uses up to about 15 MB on the phone, capped
- Storage: Stored on the phone only, never in Supabase · Effort: Medium · Gain: 5/5

### 2.3 Preload your Quick Menu pages
After a page finishes loading and the phone is idle on Wi-Fi, the app quietly preloads the code for the pages pinned in your Quick Menu.

- Pros: Your pinned pages open almost instantly; Skips itself on cellular and data saver
- Cons: Uses a little extra Wi-Fi data
- Storage: No Supabase effect · Effort: Small · Gain: 3/5

### 2.4 Split the two heaviest pages
WX Games is at 99% of its speed budget and My Profile at 96%. Each game and each profile tab would load its own code only when you open it.

- Pros: Both pages load faster; Room to add new games and profile features
- Cons: A short loading moment the first time each game or tab opens
- Storage: No Supabase effect · Effort: Medium · Gain: 4/5

### 2.5 Database tune-up
Supabase's own checker found 23 member lookups without an index, 12 overlapping read rules on the settings table that all run on every read, and 5 indexes that are never used. Add the missing indexes, merge the rules, drop the unused ones.

- Pros: Sign-in, profile, notifications and the leaderboard stay fast as membership grows; Less work for the database on every page view
- Cons: The new indexes take a few hundred KB
- Storage: About +0.3 MB, offset by the 5 dropped indexes · Effort: Small · Gain: 3/5

### 2.6 Smaller engine maps
The engine maps are the biggest thing in the database (about 140 KB each). Storing their shapes with rounded, packed coordinates makes each one roughly a third of the size, and the phone downloads less.

- Pros: The biggest table shrinks by about two thirds; Engine maps download and draw faster
- Cons: The phone unpacks the shapes (a few milliseconds); A one-time conversion of the engine code
- Storage: Saves about 1 MB now and keeps the table small for good · Effort: Medium · Gain: 3/5

### 2.7 Quiet hours for background jobs
19 scheduled jobs run all year, some every 10 minutes. Jobs that have finished their work (backfills) would stop, and storm jobs (Lightning Surge, engine maps) would slow down when there are no storms anywhere and speed back up the moment one forms.

- Pros: Far fewer server runs, so the free Vercel plan has lots of headroom; Fewer database writes
- Cons: In quiet mode a brand-new storm is picked up on the next check, at most 10 minutes later
- Storage: Fewer job-history rows (already pruned after 7 days) · Effort: Small · Gain: 4/5

### 2.8 One map per page, reused across tabs
Mapbox counts a map load every time a map starts. Pages with map subtabs start a new map per tab. Reusing one map per page keeps the count down and makes tab switches instant.

- Pros: Stays further under Mapbox's 50,000 free loads a month; Switching map tabs is instant
- Cons: A change to the shared map component, tested on every map page
- Storage: No Supabase effect · Effort: Medium · Gain: 4/5

### 2.9 Heavy math off the main thread
Soundings, the archive replay and map contouring do heavy math on the same thread that draws the screen, which can freeze taps for a moment. Moving that math to a background worker keeps the screen responsive.

- Pros: No more half-second freezes on mid-tier phones; Scrolling stays smooth while data loads
- Cons: More complex code; A little more memory while the worker runs
- Storage: No Supabase effect · Effort: Medium · Gain: 3/5

### 2.10 Smoother radar and satellite loops
Loop frames would be decoded in the background and kept ready on the graphics chip, instead of being redrawn each step.

- Pros: Loops run at full speed; Fewer out-of-memory reloads on iPhones during long loops
- Cons: iPhones older than iOS 16.4 keep today's method
- Storage: No Supabase effect · Effort: Medium · Gain: 3/5

### 2.11 Long lists draw only what's on screen
The Glossary (168 terms), Library (118 articles), warnings, gauges and leaderboard draw every row at once. They would draw only the rows you can see.

- Pros: Fast scrolling on long lists, even on older phones
- Cons: A desktop browser's find-in-page can't see rows that aren't drawn; the pages' own search still finds everything
- Storage: No Supabase effect · Effort: Small · Gain: 2/5

### 2.12 Instant page frame, data streams in
Next.js 16 can send each page's frame (title, tabs, layout) instantly from the CDN and stream the live data into it.

- Pros: Something useful on screen much sooner, especially on cellular; Feels like a native app
- Cons: The biggest change on this list: every page is reworked and retested; Sign-in checks need care
- Storage: No Supabase effect · Effort: Large · Gain: 5/5

### 2.13 Cache public database reads at the edge
News, poll results, the leaderboard, the FAQ and donation totals would be read from the database once every minute or so and served to everyone from Vercel's cache, instead of once per visitor.

- Pros: Supabase's monthly bandwidth stays tiny as members grow; These pages load faster
- Cons: New items can take up to a minute to appear (admin saves still show instantly)
- Storage: Less Supabase bandwidth; no storage change · Effort: Small · Gain: 4/5

### 2.14 Warm the cache when new data lands
When the SPC issues a new outlook or the HRRR finishes a run, a job opens the affected pages once, so the first member to visit never waits on NOAA.

- Pros: No slow first visit after each update; Fewer NOAA timeouts reach members
- Cons: A few more scheduled calls a day
- Storage: No Supabase effect · Effort: Small · Gain: 3/5

### 2.15 Lighter Library images
The Free Content Library's 418 figures are 20 MB. Each would get a phone-sized copy, so phones download about half as much per article.

- Pros: Articles open faster on cellular; Less Vercel bandwidth
- Cons: The repository grows by about 6 MB of smaller copies
- Storage: Served by Vercel, not Supabase · Effort: Small · Gain: 2/5

### 2.16 Lite mode for weak phones and data plans
A switch in Account Settings (and automatic on Android when the phone asks to save data) that uses fewer radar frames, turns off background animations and loads smaller images.

- Pros: Usable on old phones and slow connections; Saves battery during long chases
- Cons: Members who turn it on see less animation; iPhones don't report data saver, so it's manual there
- Storage: No Supabase effect · Effort: Medium · Gain: 3/5

### 2.17 React Compiler, measured
React's compiler automatically skips redrawing parts of the screen that didn't change.

- Pros: Smoother scrolling and tapping on busy pages; Less battery use
- Cons: Adds a few KB to every page; the speed budget decides; Every page needs a careful test pass
- Storage: No Supabase effect · Effort: Medium · Gain: 2/5

### 2.18 History rollover to files
Rows older than two years in the history tables (chase days, report days, archive index) move into compressed files kept in the code repository. The database stops growing with time.

- Pros: The database can never creep toward the 500 MB limit; All history stays available
- Cons: Very old history opens a little slower (read from a file); One more yearly job
- Storage: Caps database growth permanently · Effort: Medium · Gain: 3/5

### 2.19 Real-phone speed tracking
One visit in ten records how fast the page loaded and responded on that phone. Admin → Usage shows the slowest pages, so fixes go where members feel them.

- Pros: We see real speeds on real phones, not just test results
- Cons: Small database writes
- Storage: Under 1 MB, deleted after 30 days · Effort: Small · Gain: 3/5

### 2.20 Speed check before every release
Every pull request runs a speed test on 10 key pages and fails if one gets more than 10% slower, the same way the code-size budget works now.

- Pros: Slowdowns are caught before members ever see them
- Cons: Each check takes about 3 minutes longer; Uses free GitHub Actions minutes
- Storage: No Supabase effect · Effort: Small · Gain: 2/5

## 4. New pages (15)

### 4.1 Storm Mode (Severe Weather (and the homepage when it's active))
A live severe-weather hub that switches itself on when warnings are out: radar with warning boxes, every active storm ranked by ProbSevere, the storm nearest you with its arrival time, the newest reports and Mesoscale Discussions, all on one screen that refreshes itself. When warnings are near a member, the homepage leads with it.

- Why: It's the page people will open on a big day. Today the same information is spread across five pages.
- Data: NWS warnings, NOAA ProbSevere, NWS storm reports, SPC MDs (all free)
- Storage: Nothing stored; edge-cached for 1 minute · Effort: Large

### 4.2 Satellite Center (Tools & Data)
GOES-East and GOES-West loops for the whole country, your region and NOAA's one-minute storm floaters, with visible, infrared, water vapor, lightning (GLM) and the color blends forecasters use (day cloud phase, air mass, fire temperature).

- Why: Satellite is how you watch storms form before radar sees them. Radar & Model Runs has a few satellite layers; this gives satellite its own home.
- Data: NOAA GOES imagery from AWS and NESDIS (free)
- Storage: Images load straight from NOAA · Effort: Medium

### 4.3 Route Weather (Tools & Data)
Enter where you're starting, where you're going and when you leave. The route is drawn with the forecast for each stretch at the hour you'll be there: rain, snow, wind, storms and warnings along the way, with a suggested departure time to dodge the worst.

- Why: Made for chasers repositioning and for anyone driving through weather.
- Data: Mapbox Directions (100,000 free routes a month) + NWS hourly forecast
- Storage: Nothing stored unless a member saves a route (5 max) · Effort: Medium

### 4.4 Model Lab (Tools & Data)
Your location's forecast from the GFS, ECMWF, ICON, GEM, HRRR and NAM side by side, plus ensemble plumes that show how sure the models are (31 to 51 runs each). Temperature, rain, snow, wind and severe ingredients.

- Why: Radar & Model Runs compares 48 hours of temperature and rain. This adds 16 days, every variable and the ensemble spread, which shows when to trust a forecast and when to watch it.
- Data: Open-Meteo forecast and ensemble APIs (free for non-commercial use; commercial plan needed once there's revenue)
- Storage: Edge-cached, nothing stored · Effort: Medium

### 4.5 Pattern Center (Educational)
The big picture: animated jet stream and 500 mb maps for the next two weeks, where the troughs and ridges are, plus El Niño/La Niña and the teleconnection indexes (NAO, PNA, AO, MJO) explained in plain words with what they mean for your area.

- Why: Explains why the weather is doing what it's doing a week or two out, the question members ask most in quiet stretches.
- Data: NOAA GFS/GEFS, CPC teleconnection and ENSO data (free)
- Storage: Edge-cached · Effort: Medium

### 4.6 Member Storm Reports (Community)
Members report hail size, wind damage, flooding, funnel clouds and snow totals with an optional photo. Reports show on a live map; admins verify them, and verified reporters earn badges and points.

- Why: Turns the community into a spotter network and gives the team ground truth during events.
- Data: Members' reports; photos shrunk on the phone to 1280 px
- Storage: About 1 KB per report + photo (~150 KB) in the existing private bucket; deleted after 1 year; 10 photos a day per member · Effort: Medium

### 4.7 StormSync Live (Homepage tab)
The team's YouTube live streams and newest videos inside the app, with a glowing LIVE badge on the menu when anyone on the team is streaming and an optional push alert.

- Why: Brings StormSync Media's videos and the app together, so viewers become members and members become viewers.
- Data: YouTube Data API (free quota) and YouTube embeds
- Storage: Nothing stored · Effort: Small

### 4.8 Live Chase Tracker (Quick Menu)
During a chase, team members can share their live position. Members see the chasers on a radar map with warnings, their heading, and a link to their stream.

- Why: Members can follow the team chase in real time, inside the app.
- Data: Chasers' phones (opt-in, only while sharing)
- Storage: One row per active chaser, overwritten; no history kept · Effort: Medium

### 4.9 Weather Time Machine (Educational)
Pick any date since 1940 and any place: the high, low, rain, snow and wind that day, any storm reports nearby, and how it compares to normal. Great for birthdays, anniversaries and settling arguments.

- Why: Fun, personal and very shareable; brings people back.
- Data: Open-Meteo historical archive (ERA5), SPC report archive (free)
- Storage: Nothing stored · Effort: Small

### 4.10 Marine & Great Lakes (Specialty Monitoring)
Wave heights, water temperatures, wind and buoy readings for the Great Lakes and the coasts, rip current risk at beaches, and marine warnings, with a boating go/no-go for your lake.

- Why: Lake Erie is next door; boaters, anglers and beachgoers check this all summer.
- Data: NOAA NDBC buoys, GLERL Great Lakes forecasts, NWS marine zones and rip current risk (free)
- Storage: Edge-cached · Effort: Medium

### 4.11 Garden & Farm (Specialty Monitoring)
Frost and freeze alerts for tonight, first and last frost dates for your area, soil temperature for planting, growing degree days, a planting calendar and rain needed vs. received.

- Why: A big part of the audience is rural. This is a reason to open the app every day in spring and fall.
- Data: NWS, Open-Meteo soil data, NOAA freeze-date normals (free)
- Storage: Nothing stored · Effort: Small

### 4.12 Health & Comfort (Localized Data)
How the weather affects your body: heat stress, wind chill and frostbite time, UV burn time for your skin type, a pressure-change headache and joint pain outlook, and dry-air and cold-and-flu weather.

- Why: Weather everyone feels, whether or not they follow storms.
- Data: NWS forecast, EPA UV index, pressure trends (free)
- Storage: Nothing stored · Effort: Small

### 4.13 Spotter Academy (Educational)
An interactive storm-spotter course: short lessons with real storm photos and radar, quizzes that ask you to find the wall cloud or the hook echo, and a certificate badge at the end. Points count toward the leaderboard.

### 4.15 Snow Day Predictor (Localized Data (winter))

- Why: Students and parents check this every winter night; it's the kind of thing people share.
- Data: NWS hourly forecast, WPC winter guidance, members' reports

## 5. Extras engines

### Deer & Fishing fix
Each spot's best hour always lands at dawn or dusk, and dawn and dusk score about the same everywhere, so the old smooth map filled one band and the dot map that replaced it barely changes from place to place.

1. Score the weather, not the clock: the map uses what changes from place to place (temperature against the past week, pressure trend and fronts, wind, rain, the rut and the moon for fish). Dawn and dusk stay in the hour-by-hour readout where they belong.
1. Compute on the HRRR and GFS grids the other engines already read, for the area you choose below, stored per run and overwritten, so storage stays flat.
1. Draw it like the SPC: smooth, nested, filled areas with dark outlines, a label on each area, a legend box, Day 1 / Day 2 / Day 3 tabs, the issue time, and tap-anywhere details.
1. Categories in SPC's colors: Slow (no color, like SPC's blank areas), then Fair, Good, Very Good, Excellent and Peak (Peak is the rare top tier, like SPC's High). Fishing keeps its species buttons.

### New engines (15)

### 5.1 Machine-Learning Severe Outlook (Python)
A model that learned from 20+ years of NOAA forecasts and every storm report what kind of setup produces tornadoes, hail and damaging wind. It draws its own Day 1–3 severe outlook to compare with the SPC's.

- How: Python (scikit-learn) on GitHub Actions, trained once on NOAA's free GEFS reforecast archive; it reads each new GEFS run and stores a small map per day.
- Accuracy (4/5): Good. Colorado State's research version of this method scores close to the SPC's own outlooks on Days 2 and 3. Ours is checked daily against SPC reports, like the current engines.
- Pros: An independent second opinion on severe days; Can go out to Day 3, where few tools exist
- Cons: The biggest build here: training takes a few days of work; Weaker on rare setups the past seldom saw

### 5.2 Overshooting Top Detector (Python)
Finds storm tops punching up through the anvil on satellite. Those are the strongest updrafts, often 10–30 minutes before large hail, damaging wind or a tornado.

- How: Python reads GOES infrared and visible data from AWS every 5 minutes and looks for small spots much colder than the anvil around them (NASA's published method).
- Accuracy (4/5): Good at finding strong updrafts. Not every overshooting top turns severe, so it's an early heads-up, not a warning.
- Pros: Works where radar can't see (gaps, at night, offshore); Early heads-up for chasers
- Cons: Runs every 5 minutes during storms (GitHub Actions minutes); Thin cirrus can hide tops

### 5.3 Tornado Debris Finder (Python)
Scans every NEXRAD radar for the debris signature: a tornado lofting debris shows as a small spot of low correlation inside a rotation couplet. It marks likely confirmed tornadoes on the map within minutes.

- How: Python with Py-ART reads Level 2 radar from AWS and checks correlation coefficient, velocity and reflectivity together.
- Accuracy (5/5): High when it finds one: a debris signature is close to proof of a tornado on the ground. It misses weak tornadoes and anything far from a radar.
- Pros: Near-confirmation within minutes; A strong tool for Storm Mode and the Tornado Archive
- Cons: Heavy data: only scans radars inside tornado warnings; Only sees tornadoes that are already damaging something

### 5.4 Flash Flood Nowcast
Shows where the rain that has already fallen is more than the ground can take, using the same test NWS forecasters use: radar rainfall over 1, 3 and 6 hours against NOAA's flash flood guidance.

- How: Reads MRMS rainfall and NWS flash flood guidance grids every 10 minutes; draws areas by how far over the guidance they are.
- Accuracy (4/5): Good. It's the NWS method. Urban areas flood sooner than the guidance says; burn scars are flagged separately.
- Pros: Fills a gap: Flooding Outlook covers forecasts, this covers right now; Feeds Storm Mode
- Cons: Radar can under- or over-count rain near mountains and far from a radar

### 5.5 Ice Storm Accretion
How much ice will build up on trees and power lines during freezing rain, and where it will be enough to bring down limbs and wires.

- How: The NWS Freezing Rain Accumulation Model (FRAM) applied to HRRR precipitation, temperature and wind.
- Accuracy (4/5): Good when the model has the precipitation type right; ice totals are hard for any model when the freezing line is close.
- Pros: Ice is the most damaging winter hazard and has no page of its own; Pairs with the Blizzard Composite
- Cons: Only matters a few days a winter

### 5.6 Power Outage Risk
A map of where power outages are likely in the next 48 hours, from gusts, ice, wet ground that lets trees topple, and whether the trees still have leaves.

- How: HRRR and GFS gusts, ice accretion and soil moisture, weighted by season and tree cover; checked against public outage reports.
- Accuracy (3/5): Fair. Outages depend on local trees and lines no model sees. It shows risk, not exact outages.
- Pros: Everyone understands it; Useful for Disaster Response planning
- Cons: Rougher than the storm engines

### 5.7 Storm Complex & Derecho Paths
Where a cluster of storms (an MCS or derecho) will move overnight, using Corfidi vectors: arrows showing whether the complex will race downwind or back-build and train over the same towns.

- How: Mean cloud-layer wind and low-level jet from the HRRR, drawn as arrows over the storms and outlined where training (flooding) is likely.
- Accuracy (4/5): Good for direction (a long-standing forecaster method); speed is rougher.
- Pros: Answers the night-time question: is it coming here?; Pairs with the Derecho Composite
- Cons: Needs a storm complex to exist or be forecast first

### 5.8 Supercell Paths
The path a supercell will take after it forms, for right-moving and left-moving storms, drawn as arrows across the risk area.

- How: The Bunkers storm-motion method on HRRR winds, plus storm-relative inflow to show which storms will feed best.
- Accuracy (4/5): Good. The Bunkers method usually lands within about 10 mph of the real motion.
- Pros: Chasers can plan an intercept before storms even fire; Shows which roads run with the storm
- Cons: Storms that turn on boundaries won't follow it

### 5.9 Microburst Potential
Where summer storms can drop sudden, damaging downbursts, even from storms that look ordinary on radar.

- How: The Microburst Day Potential Index and the Wind Index (WINDEX) from HRRR temperature and moisture profiles.
- Accuracy (3/5): Fair to good on summer afternoons; it shows where downbursts can happen, not which storm will do it.
- Pros: Covers the most common summer wind damage; Useful for outdoor events and pilots
- Cons: Mostly a summer tool

### 5.10 Lake-Effect Snow Bands
Where the Great Lakes snow bands will set up, how intense they'll be and how long they'll sit over one place.

- How: Lake water temperature against the air above it, wind direction and fetch across each lake, and the height of the inversion, from the HRRR and GLERL lake temperatures.
- Accuracy (3/5): Fair to good. Band placement can shift 10–20 miles with small wind changes; intensity is better.
- Pros: Lake Erie's snowbelt is in our backyard; Different from the retired Snow Squall engine (that was squall lines; this is lake bands)
- Cons: Only for the Great Lakes, November to February

### 5.11 True Snowfall
Snowfall totals that account for how fluffy or wet the snow will be, instead of the usual 10 inches of snow per inch of water.

- How: The Cobb snow-ratio method on HRRR and GFS temperature profiles through the snow-growth zone.
- Accuracy (4/5): Good. Usually closer to measured totals than the 10:1 rule, especially in very cold or very wet storms.
- Pros: Totals people can trust; Feeds the Winter Center and the Snow Day Predictor
- Cons: Only as good as the model's precipitation amount

### 5.12 Frost & Freeze Tonight
Tonight's frost and freeze map, down to the valleys where cold air pools, with the time it'll reach 32°F where you are.

- How: HRRR 2 m temperature and dew point, sky cover, wind and terrain (cold air drains into low spots).
- Accuracy (4/5): Good on clear, calm nights, which is when frost happens.
- Pros: Gardeners and farmers check it every spring and fall; Pairs with the Garden & Farm page
- Cons: Seasonal

### 5.13 Fog Forecaster
Where dense fog will form overnight and when it will burn off in the morning.

- How: HRRR visibility, low-level humidity, light wind and clear skies at night, with the morning sun angle for burn-off.
- Accuracy (3/5): Fair. Fog is one of the hardest things to forecast; the HRRR is the best free model for it.
- Pros: Matters for every morning commute
- Cons: Patchy valley fog is often too small for the model

### 5.14 Heat Stress (WBGT)
Wet Bulb Globe Temperature: the heat measure coaches, the military and outdoor workers use, which counts sun and wind, not just heat and humidity. Flags when practices and work should change.

- How: The published Liljegren method on HRRR temperature, humidity, wind and sunshine, hourly.
- Accuracy (4/5): Good; NWS runs an experimental WBGT forecast with the same method.
- Pros: Real safety value for schools and sports; Pairs with Health & Comfort
- Cons: Summer only

### 5.15 Drone Flying Forecast
A fly / caution / don't-fly score for drones over the next 24 hours: winds and gusts at 0–400 ft, rain, visibility, cold that drains batteries, and solar storms that upset GPS.

- How: HRRR winds at 10 m and 80 m, gusts, precipitation, visibility, temperature and NOAA's Kp index.
- Accuracy (4/5): Good for wind, the thing that grounds drones most.
- Pros: Many chasers fly drones for footage; Simple and useful every day
- Cons: Doesn't know about airspace rules; it links to the FAA's map

## 7. Review

### Looked at
- All 906 source files: 46 pages, 40 admin sections, 25 menus, 20 engines and 7 Randoms, the API routes, the shared map, theme and menu systems
- The docs: build status, phase list, every owner decision, the build plan and its 118-entry bug log
- Supabase live: size (20 MB of 500 MB), every table, all 19 scheduled jobs, and its performance and security checkers
- The live site at weather.sswx.space on a phone-sized browser
- Your four screenshots (Hive, Account Settings with Ribbon Fold, Deer and Fishing)

### Good
- **Huge, real coverage.** Severe, tropical, winter, fire, sky, history, the archive, the chase log, games and engines in one app, all on live NOAA data with no fake numbers anywhere.
- **Storage discipline.** 20 MB of a 500 MB database after all of this. Every growing table has a retention rule that a test enforces, a daily watchdog emails at 60% and 80%, and no images live in Supabase.
- **Speed discipline.** Every page has a code-size budget that blocks a release if it's broken, about 80 data routes are cached at the edge, menus load only when chosen, and slow phones get lighter motion automatically.
- **Security.** Row Level Security on every table, secrets kept on the server, PINs never stored, and the admin database functions check permissions themselves (I tested a sample).
- **One design language.** Themes are pure color swaps, every map color is editable in admin with a live preview, and pages share the same hero, cards and glow.
- **The admin panel.** Owner-level control of nearly everything: view as a member, kill switches, menus, colors, Extras switches, audit log, health and storage.
- **Engines that check themselves.** Each engine logs where it pointed and checks it against what happened; members' reports tune the outdoor engines.

### Needs work
- **Deer and Fishing maps.** Dots over Ohio instead of the SPC-style map you wanted (fix planned in tab 5).
- **Hive words off center.** Each hexagon's side padding is a percentage, which iPhone Safari measures against the whole row instead of the hexagon. Wider rows squeeze the text box to almost nothing, so words spill to the right. The middle row in your screenshot is off the most, which matches.
- **Ribbon Fold button stays tilted.** The button tilts when hovered. Phones keep a 'hover' after a tap, so after you close the menu the button stays tilted until you tap somewhere else.
- **Old app files pile up on phones.** The offline helper never deletes old versions' code (performance item 1).
- **Two pages can't grow.** WX Games is at 99% and My Profile at 96% of the speed budget, so anything added there has to wait for a split.
- **Background jobs run all year.** 19 jobs, some every 10 minutes even on quiet winter days. The free Vercel plan doesn't charge overage; it pauses. There's headroom today, but it shrinks as features are added.
- **Guests and Google can't see much.** Only 5 pages are open without an account, so search engines can't index the app and a shared link to most pages lands on the sign-up gate.
- **Database housekeeping.** 23 unindexed member lookups, 12 overlapping read rules on the settings table, 5 unused indexes, and the retired disaster_volunteers and game_winners tables are still there.
- **25 menus to maintain.** Every change to the app's layout has to be checked against all of them. The menu manager in tab 3 lets you keep the best.
- **Open-Meteo once there's revenue.** Nine data routes (Storm Chasing Outlook, SSWXCon local, Ingredients, Winter, sky grid, AQI, Deer and Fishing, model compare, nowcast) use Open-Meteo's free API, which is for non-commercial use. With paid plans live, it needs their commercial plan or a switch to NOAA sources for those routes.
- **Waiting on keys.** Real pollen counts (Google Pollen key) and AirNow AQI still need their free keys added in Vercel.

### Three things I'd add
- **Storm Mode.** A live severe-weather hub that turns on by itself when warnings are out and takes over the homepage for members near the storms. It's the single biggest upgrade for a storm-chasing brand: on the day it matters, one screen has everything.
- **A public front door.** Open, Google-searchable teaser versions of the best pages (SSWXCon, the outlooks, On This Day, the Glossary, the Library) with share images of today's maps generated automatically. Every post on social media then links into the app and brings sign-ups.
- **StormSync Live + Chase Tracker.** The team's live streams and live chaser positions together on one radar map during events. Members watch the team chase from inside the app, which is something no other weather app can offer.
